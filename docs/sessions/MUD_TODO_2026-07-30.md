## Prioridad 0: Entrenar un modelo LLM solo con ASM

### Objetivo
Implementar el entrenamiento completo de un modelo LLM (forward + backward + optimizer) usando **únicamente ASM x86_64**, sin código Rust en el hot path. Esto aprovecha al máximo cada ciclo de reloj del procesador.

### Componentes ASM necesarios

#### 1. Forward pass (ASM puro)
- **`ternary_gemv_8rows.s`** — ya existe, optimizar con `vpmovzxbd` + `vpermd`
- **`rmsnorm.s`** — ya existe, optimizar con `vmaxps` + `vandnotps`
- **`silu.s`** — ya existe, optimizar con `vpternlogd`
- **`rope.s`** — ya existe, optimizar con `vpermd`
- **`q4_0_gemv.s`** — ya existe para F32 weights

#### 2. Backward pass (ASM nuevo)
- **`backward_ternary_gemv.s`** — dL/dW = grad_y ⊗ x^T (outer product AVX2)
- **`backward_rmsnorm.s`** — dL/dx = grad_y * (rms_inv * weight)
- **`backward_silu.s`** — dL/dx = grad_y * silu'(x) (derivada de SiLU)
- **`backward_rope.s`** — dL/dx = rotate(grad_y) (inverso de RoPE)

#### 3. Optimizer (ASM nuevo)
- **`adam_step.s`** — ya existe, revisar y optimizar
- **`sgemm.s`** — ya existe para GEMM
- **`apply_scales.s`** — ya existe para aplicar scales

#### 4. JEPA + mHC (ASM nuevo)
- **`jepa_ou.s`** — z = 0.9·z + 0.1·y_norm (EMA con FMA)
- **`mhc_gate.s`** — gate = sigmoid(v_jepa) (con lookup table AVX2)

### Instrucciones clave a usar
| Instrucción | Uso |
|------------|-----|
| `vfmadd231ps` | FMA: acc += a*b (1 ciclo) |
| `vpmovzxbd` | i8→i32 zero-extend (ternary unpack) |
| `vpermd` | Permutación de 8 enteros (transpose) |
| `vgatherdps` | Gather disperso (GEMV con stride) |
| `vpmaxsb` | Max de 32 i8 (peak-finding) |
| `vpternlogd` | Operación ternaria lógica (máscaras) |
| `vandps` | AND vectorial (máscara branchless) |
| `vcmpps` | Comparación vectorial (gate) |
| `vmovmaskps` | Extracción de máscara (gate) |

### Ventajas de ASM puro
1. **Cero overhead de Rust** — no hay bounds checking, no hay LLVM IR intermedio
2. **Control total de registros** — YMM0-YMM15 asignados manualmente
3. **Instrucciones específicas** — `vfmadd231ps`, `vpmovzxbd`, `vpermd` directamente
4. **Scheduling manual** — evitar stalls de pipeline con instrucciones independientes
5. **Non-temporal stores** — `vmovntps` para evitar cache pollution en writes grandes

### Métricas objetivo
- **Forward GEMV:** 8 f32/iteración (AVX2) → 16 f32/iteración (AVX-512, si disponible)
- **Backward outer product:** 8 f32/iteración (AVX2 FMA)
- **Optimizer:** 8 f32/iteración (AVX2 FMA)
- **tok/s:** debe mejorar de 1.2 a ≥2.0 (70% más rápido)
- **103.7s/chunk → ≤70s/chunk** (32% más rápido)

## Prioridad 3: Optimización `f32_gemv_backward` GEMV (dL/dx)

### Problema actual
El GEMV dL/dx itera sobre `n_out` filas y acumula en `grad_x` (n_in elementos). Cada fila hace un `_mm256_fmadd_ps` de 8 elementos. Esto es O(n_out × n_in/8).

### Optimización propuesta
- Usar **transposición de bloques** (8×8) para convertir el GEMV en un pattern más cache-friendly
- O usar **`vgatherdps`** para gather de columnas (si n_out es pequeño)
- O usar **non-temporal stores** (`_mm256_stream_ps`) para `grad_x` si es muy grande

## Prioridad 4: Optimización `slime_forward.rs` FFN GEMV

### Problema actual
El FFN forward GEMV (`f32_gemv_rowwise_submit`) usa `dot_product_avx2` por fila, paralelizado con PCorePool. Pero el GEMV de salida (LM head) puede ser optimizado.
