## 1. Context & Issue Resolution

Following the implementation of the `f32` SlimeRegister accumulation matrix (Priority 27), the model faced a catastrophic OutOfDeviceMemory (OOM) error during the Vulkan backward QAT pass. The VRAM footprint ballooned to ~17.5 GB, exceeding consumer hardware limits.

### The Fix
We identified that `shadow_w_cache` (the FP32 persistent state of the weights) was being permanently allocated in VRAM for all 30 layers.
- **Action:** Refactored `qat_dispatcher.rs` to treat the shadow weights buffer as an **ephemeral buffer** keyed by `tensor_type` (e.g., `"attn_q"`). 
- **Result:** The FP32 shadow state is now dynamically streamed back and forth via the async `download_queue`. This reduced the VRAM footprint for the QAT dispatcher from ~17.5 GB down to an incredibly efficient **~316 MB**. The model now processes hundreds of batches smoothly with `0` OOM crashes.
