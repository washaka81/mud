# MUD Engine - Actualización y Notas de Lanzamiento (2026-07-22)

Este documento detalla todas las correcciones, integraciones y mejoras preparadas para subir a GitHub en esta revisión. Garantiza estabilidad local, precisión en el entrenamiento y mejoras en la interfaz.

## 1. Pipeline de Entrenamiento y Corpus

- **Corrección Crítica de Duplicación de Corpus:** Se arregló un bug en `src/mud/corpus_trainer.rs` por el cual el archivo maestro generado por `mud.sh` (`project_corpus.txt`) era leído y consumido dos veces por época. Ahora, la recolección (`collect_files`) excluye implícitamente este archivo, garantizando que el modelo consuma la información una sola vez sin distorsionar la convergencia (Perplexity).
- **Precisión de Métricas (ETA & Tok/s):** La matemática para calcular el tiempo estimado (ETA) y los tokens por segundo (`tok/s`) ha sido ajustada y calculada post-división de chunks para asegurar que las proyecciones de velocidad en el TUI del entrenador sean fieles a la realidad.
- **Bypass de Límite de Chunks:** Se modificó `mud.sh` para que, cuando el usuario pida entrenar por épocas completas (ej. `--epochs 10`), el límite hardcodeado de `MAX_CHUNKS` se deshabilite automáticamente, permitiendo sesiones largas sin interrupciones tempranas por error.

## 2. Motor de Inferencia y Tokenizer

- **Fusión de Palabras (Word Fusion Bug):** Se arreglaron el cargador de datos `corpus_trainer.rs` y el validador `cmud_train.rs` para tokenizar documentos continuos correctamente, preservando el prefijo de espacio `Ġ` entre saltos de línea y fragmentos (`chunk boundaries`). Se añadió la función `Tokenizer::has_space_prefix` y su test unitario para blindar esto.
- **Conversor Universal Sano (`FIX D`):** Se ha validado la corrección del offset del mmap en `MudFile::save` (usando `data_base + offset`). Las reconstrucciones del archivo `.mud` ya no se corrompen ni inflan las escalas (`~±1e38`), permitiendo un entrenamiento y chat sanos.

## 3. C-MUD (Complex-MUD Manifold) & CMUX (Thinker)

- **Actualización de `.gitignore`:** Se incorporaron explícitamente los formatos del manifold C-MUD al archivo `.gitignore`:
  - `*.cmud`, `*.cmux`, `*.thinker`, `*.think`
  - *Explicación (CMUX como Thinker):* El "CMUX" (Context Multiplexer) y los archivos *sidecar* JSON asociados a las trazas y amplitudes de fase actúan como el "Thinker" del modelo, permitiendo razonamiento complejo persistente estilo *DeepSeek-V4* en el espacio continuo sin entorpecer el historial de git.
- **C-MUD Manifold Validator:** Nueva herramienta `cmud_manifold_validator` (`./mud.sh cmud-manifold`) implementada para comparar la inferencia basal vs. C-MUD, evaluando el desempeño del *thinker* en 5 dimensiones cognitivas (Léxico, Pensamiento, Coherencia, Resolución de Problemas, Resultados) usando un formato de tabla verificable 100%.

## 4. Vulkan, Arquitectura y UI

- **Mantenimiento del `Cargo.toml`:**
  - Se añadieron dependencias críticas para el soporte gráfico Vulkan: `gpu-allocator = "0.28.0"`.
  - Se actualizó el target de `ash` a `"0.38.0"`, alineando la versión con el soporte de hardware *Iris Xe*.
  - Se limpiaron binarios "huérfanos" (ej. `training_estimator`, `awake_aligner`) que generaban falsos negativos.
- **Cero Advertencias (0 Warnings):** El proyecto vuelve a tener un estado 100% puro al correr `cargo clippy --all-targets` sin mostrar errores de módulo.
- **Formato y Tablas UI:** Se integró la librería `unicode-width` (`UnicodeWidthStr`) en todos los CLI y UIs del entorno para asegurar bordes de caja con píxeles perfectos y soporte limpio para caracteres UTF-8 de control como `Ġ`, `Δ`, `µ`, y `τ`.
